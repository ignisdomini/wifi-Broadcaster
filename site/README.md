# РАДИОИНФОРМАТОР — сеть приложения ЭФИР

[![Лицензия Apache 2.0](https://img.shields.io/badge/лицензия-Apache%202.0-blue.svg)](../LICENSE)
[![PHP 8](https://img.shields.io/badge/PHP-8.0%2B-777bb4.svg)](https://www.php.net/)

Серверная часть [приложения ЭФИР](https://www.rustore.ru/catalog/app/ru.radioinformator.efir):
личные ленты, куда попадают опубликованные передачи, витрина сети и админка.

Сам обмен сообщениями идёт **мимо этого сайта** — напрямую между телефонами по
Wi-Fi Direct. Сайт нужен только для необязательной ленты: длинный текст
ложится сюда, а в эфир уходит короткий код страницы. Личные сообщения сюда не
попадают вообще.

**Чистый PHP 8 и MySQL, без composer, node и сборки.** Работает на любом
обычном хостинге: распаковали, открыли `install.php`, ответили на вопросы.

| | |
|---|---|
| **Нужно** | PHP 8.0+, MySQL 5.7 / MariaDB 10.3+ |
| **Установка** | [INSTALL.txt](INSTALL.txt) — по шагам |
| **Живая сеть** | [radioinformator.ru](https://radioinformator.ru) |

## Быстрый запуск для разработки

```bash
php -S 127.0.0.1:8831 -t . router.php
```

`router.php` нужен только локально: на хостинге его роль выполняет `.htaccess`.
Доступ к базе лежит в `config.php` — он создаётся установщиком и **в
репозиторий не попадает**; образец полей смотрите в `lib/config.sample.php`.

У каждого позывного своя лента: туда попадает то, что он передал по воздуху, —
короткая строка из эфира и прикреплённый к ней текст.

Это **не чат и не общая лента**. Общего потока сообщений на сайте нет вообще:
главная — это объяснение порядка и одно действие, ввести код чужой ленты.

Чистый PHP 8 + MySQL 8, без composer и сборщиков — рассчитано на обычный
шаред-хостинг.

## Чего здесь нет и почему

Сайт сделан вокруг цифрового благополучия, поэтому часть привычных вещей
отсутствует намеренно, а не по недоделке:

- **Файлов не бывает.** Прикрепить можно только текст. Фотография превращает
  короткую записку в архив, который потом жалко разбирать, а хранилище — в то,
  что надо обслуживать. Попытка отправить файл получает честный отказ
  `FILES_NOT_ACCEPTED`.
- **Ленты, которую можно листать, нет.** Ни общего потока, ни рекомендаций,
  ни бесконечной прокрутки. Заходят сюда по поводу и уходят, прочитав.
- **Счётчик просмотров не показывается.** Он считается для администратора, но
  автору и читателю не виден: это соревнование ни к чему.
- **JavaScript не используется.** Ни строчки: нечему обновляться в реальном
  времени и незачем.

## Главная мысль устройства

**Списка людей и поиска по людям здесь нет и не будет.** Личная лента живёт по
адресу `/u/<двенадцатизначный код>`; код не выводится из позывного, нигде на
сайте не публикуется и закрыт от поисковиков (`noindex` + `robots.txt`).
Единственный способ его получить — поймать передачу этого человека в эфире: код
едет в той же TXT-записи, что и текст. Знакомятся здесь только вживую, на
расстоянии приёма Wi-Fi.

Форма на главной — не поиск: она открывает ленту по уже известному коду.
Подобрать его нельзя, вариантов 31¹².

## Оформление

Светлое и обыденное: тёплая бумага `#FBF8F4`, оранжевый сигнал `#E8590C`,
крупный шрифт, ясные карточки. Этим пользуются продавец на рынке и хозяйка
кафе, а не любители радио, — поэтому никакого тёмного «хакерского» вида.

**Всё движение сделано на CSS.** Скриптов на сайте нет ни строчки. Любая
анимация выключается при `prefers-reduced-motion`: эффекты здесь украшают, но
ни один из них ничего не сообщает, и без них страница не теряет смысла.

## Анонимность учётной записи

Учётка — это позывной и кодовое слово, больше ничего: ни почты, ни телефона,
ни привязки к устройству.

Кодовое слово на сервер не приходит вообще. Приложение считает
`auth_key = sha256(позывной в нижнем регистре + ':' + кодовое слово)` и шлёт
только его; сервер хранит `password_hash(auth_key)` плюс `sha256(auth_key)` —
последнее нужно, чтобы найти владельца по ключу, не называя позывного (он
кириллический, а не-ASCII в HTTP-заголовке не выживает).

Следствие честное и его стоит понимать: **забытое кодовое слово не
восстанавливается.** Ни владельцем сайта, ни поддержкой — восстанавливать
попросту нечем.

## Каналы

Настоящую радиочастоту у Wi-Fi Direct задать нельзя — обнаружение служб живёт
на социальных каналах 1/6/11. Поэтому «частота» здесь логическая: номер канала
едет в TXT-записи, а приёмник отбрасывает всё, что пришло не на его канале.
Каналов 16, и они тематические: общий, еда и кафе, скидки, рынок, туризм,
тревога, объявления, знакомства, сообщества, события, транспорт, работа и
четыре свободных. По умолчанию слушается общий и тревожный.

Сетка задана в `lib/channels.php` и отдаётся приложению через `/api/limits.php`.

## Установка

1. Залить каталог в корень сайта.
2. Открыть `/install.php`, указать доступ к базе и задать пароль администратора.
3. Удалить `install.php` — админка напомнит об этом сама.

## Обновление

Перезаписать файлы, не трогая `config.php`, и открыть `/update.php` под
администратором (либо `php update.php` из консоли). Скрипт догоняет схему,
убирает файлы прежних версий и перечисляет остатки, которые трогать не
вправе, — таблицу `images`, каталог `uploads`, забытый `install.php`.

Запускать можно многократно: сделанное пропускается. Шаги живут в
`lib/migrations.php` — единственном месте, откуда их берут и `update.php`,
и оставленный для совместимости `migrate.php`.

Настройки обновление не меняет. Новые значения по умолчанию (снятый лимит
записей в час, название сети) действуют только для новых установок — на
работающей сети их правят в админке.

## Устройство

## Личные сообщения

Их на сайте нет и не будет: они живут только в эфире. Приложение шифрует текст
ключом получателя и вещает его отдельной службой — сюда такие сообщения не
попадают вообще, а публичные ключи ездят в TXT-записях, минуя сеть. Подробности в README приложения.

Сайт участвует ровно в одном: он хранит позывной и ленту, чтобы человек мог
вернуться к ним с нового телефона.

## Состав

```
index.php            главная — объяснение порядка и вход в ленту по коду
u.php                личная лента, /u/КОД (noindex)
p.php                отдельная запись, /p/КОД
api/register.php     регистрация и вход одним обращением
api/limits.php       лимиты и сетка каналов для приложения
api/upload.php       приём записи (только текст, файлы отклоняются)
api/profile.php      визитка на странице ленты: чтение и правка
admin/               вход, сводка, записи, позывные, настройки
lib/                 конфиг, БД, настройки, каналы, записи, пользователи, визитка
assets/              стили и favicon
migrate.php          догоняет схему на установленном сайте
router.php           только для локального php -S
```

## API

### `POST /api/register.php`

Поля формы: `handle`, `auth_key`. Свободный позывной занимается, занятый пускает
внутрь при верном ключе — регистрация и вход это одно действие, потому что при
полной анонимности «восстановление доступа» взять неоткуда.

```json
{"ok":true,"created":true,"handle":"Костя","profile_code":"uuq5qjh3nynp",
 "profile_url":"https://radioinformator.ru/u/uuq5qjh3nynp","posts_count":0}
```

### `GET /api/limits.php`

Лимиты, сетка каналов и требования к токену. Приложение спрашивает это при
запуске: всё задаётся в админке, а не в сборке APK.

### `POST /api/upload.php` (multipart/form-data)

| Что | Где |
|---|---|
| `broadcast` | короткая строка, ушедшая в радиоэфир |
| `text` | длинный текст |
| `channel` | логический канал 1..16 |
| `X-Efir-Auth` | заголовок с `auth_key` — по нему находится автор |
| `X-Efir-Token` | заголовок с токеном, если он задан в админке |

Любой присланный файл приводит к отказу `FILES_NOT_ACCEPTED` (422). В
`/api/limits.php` поле `max_images` отдаётся равным нулю — чтобы старые сборки
приложения не предлагали выбрать фото.

### `GET /api/mine.php`

Своя лента: записи владельца ключа (заголовок `X-Efir-Auth`), включая скрытые
премодерацией — хозяин должен понимать, почему его запись не видна.

### `GET`/`POST /api/profile.php`

Визитка на странице ленты: имя или название, телефон, почта, сайт, Telegram, VK
и строка с остальными соцсетями. `GET` отдаёт текущие значения, `POST` их
сохраняет — оба по заголовку `X-Efir-Auth`.

Поле, которого нет в запросе, считается пустым: так приложение стирает строку,
просто не прислав её. Поле `public=0` прячет визитку целиком, не стирая
заполненного.

Telegram, VK и сайт нормализуются при сохранении: `@name`, `t.me/name` и
`https://t.me/name` превращаются в `name`, из адреса сайта убирается схема.
Хранится короткая форма, ссылки собираются при выводе.

Это единственное место, где сеть что-то знает о человеке, и заполняется оно
только по своей воле: по умолчанию все поля пусты и на странице ленты не
показывается ничего. Формы на сайте нет намеренно — править визитку можно
лишь из приложения, потому что кодовое слово телефон не покидает.

### `POST /api/delete.php`

Удаление своей записи по полю `code`. Проверяется не только ключ, но и
принадлежность: даже с верным ключом чужое не удалить. Ответ на попытку
тронуть чужую запись такой же, как на несуществующую, — чтобы по нему нельзя
было выяснять, какие коды заняты.

Управлять лентой можно только из приложения: на сайте для этого пришлось бы
вводить кодовое слово, а оно телефон не покидает.

Позывной берётся из учётной записи, а не из тела запроса: иначе можно было бы
подписаться чужим именем. Без `X-Efir-Auth` передача всё равно принимается, но
не попадает ни в чью ленту — в ответе это видно по `in_feed`.

## Что настраивается в админке

- **Содержимое** — отдельная вкладка: все тексты главной страницы, от заголовка
  до подписи в подвале. Ни одной надписи не зашито в шаблон; опись полей одна
  и та же для формы, приёма данных и возврата к исходным (`lib/content.php`).
  Пустой заголовок карточки убирает её со страницы целиком.
- **Сайт**: название, подпись, адрес.
- **Текст**: максимальная длина записи; длина радиосообщения в байтах.
- **Порядок**: записей с одного адреса в час (по умолчанию 0 — без
  ограничения), срок хранения, токен для приложения, премодерация.
- **Позывные**: просмотр и блокировка. Публичного списка при этом не появляется.

## Решения, которые стоит знать

- **Короткий код записи — 5 символов, код ленты — 12**, оба из алфавита без
  похожих знаков (нет `0`, `o`, `1`, `l`, `i`). Первый читают с экрана, второй
  должен быть неперебираемым.
- **IP хранится только хешем** с солью из `config.php`.
- **Срок хранения — это не уборка ради места, а часть замысла.** Задайте
  `retention_days`, если хотите, чтобы старое забывалось само.

### Если сайт обновляется со старой версии

Приём файлов убран, но `migrate.php` **не удаляет** таблицу `images` и каталог
`uploads`: это чужие данные, и решение принимает владелец сайта. Миграция
только сообщает, сколько там записей. Удалять — вручную:

```sql
DROP TABLE images;
ALTER TABLE posts DROP COLUMN images_count;
```

## Локальный запуск

```bash
php -S 127.0.0.1:8828 -t D:/CLAUDE/efir-site D:/CLAUDE/efir-site/router.php
```

`router.php` подменяет `.htaccess`: разбирает `/p/КОД` и `/u/КОД`, закрывает
`lib/`, а на несуществующий путь в `/api/` отдаёт 404, а не главную —
иначе удалённый эндпоинт локально «работает».
